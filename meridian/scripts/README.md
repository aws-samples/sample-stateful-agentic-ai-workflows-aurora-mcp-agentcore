# Meridian operator scripts

Run from `meridian/` with the virtual environment active. Follow
[Operations](../docs/OPERATIONS.md) for complete commands and prerequisites.
The numbered capability source lives in [backend/agents](../backend/agents/README.md);
these shared scripts keep one stable command path for operators and CI.

| Step | Scripts | Effect |
| --- | --- | --- |
| **01 - Prepare** | `setup.sh`, `verify_installation.py`, `provision_preflight.py` | Local setup and read-only provisioning checks. Aurora provisioning and teardown use the CDK app in `infra/`. |
| **02 - Load Aurora** | `init_aurora_schema.py`, `apply_migrations.py`, `seed_data.py`, `travel_catalog.py` | Write schema, tracked migrations and sample catalog. Initialization and seeding refuse existing data. Never delete or reorder migration history. |
| **03 - Bind identity** | `bind_current_identity.py`, `bind_gateway_workload.py`, `bind_web_backend_role.py`, `apply_rls_force_and_decoy.py` | Write workload grants or demonstration RLS policies. Review the target first. |
| **04 - Configure AgentCore** | `render_agentcore_config.py`, `sync_agentcore_env.py`, `publish_gateway_parameters.py` | Render ignored account-specific config, optionally update local environment, publish SSM settings (a dry run unless given `--apply` and the confirmation flag). See the AgentCore runbook. The render needs `AURORA_GATEWAY_SECRET_ARN`, set by `provision_service_logins.py --login gateway --apply --write-env`, which requires migration 018 applied first. |
| **04b - Workflow Runtime** | `provision_workflow_login.py`, `stage_workflow_runtime.py`, `bind_workflow_runtime.py`, `smoke_workflow_runtime.py` | `provision_workflow_login.py` gives the `meridian_workflow` login a password in Secrets Manager and creates its access policy; without `--apply` it only reports, and running it again rotates the password. `stage_workflow_runtime.py` copies the workflow's backend modules into the Runtime bundle, and the render runs it. `bind_workflow_runtime.py` writes the Runtime role's traveler binding. `smoke_workflow_runtime.py` pings the deployed Runtime and touches no row. Order is in the runbook's workflow Runtime steps. |
| **04c - Service logins and sign-in** | `provision_service_logins.py`, `seed_cognito_users.py`, `sync_cognito_env.py`, `cognito_tokens.py` | `provision_service_logins.py` gives the backend, gateway and identity logins their passwords, secrets and managed policies; it needs migration 018 and, without `--apply`, only reports. `seed_cognito_users.py` creates the two sign-in users and their bindings, and a re-run repairs a partial run. `sync_cognito_env.py` copies the identity stack outputs into `.env` and `frontend/.env.development.local`. `cognito_tokens.py` mints real tokens for tests. Steps and rollback are in [Operations](../docs/OPERATIONS.md#service-logins). |
| **04d - Identity harness** | `run_gateway_harness.py` | Dry run by default (no AWS call); it prints the plan and the tag permissions the profile needs (`lambda:TagResource`, `lambda:ListTags`, `iam:TagRole`, `iam:ListRoleTags`, `bedrock-agentcore:TagResource`, `bedrock-agentcore:ListTagsForResource`). `--apply --i-understand-this-creates-aws-resources` creates a separate throwaway Gateway named `meridian-throwaway-<id>`, probes it with the real Jordan and decoy tokens, prints a verdict table and deletes everything. `--teardown LEDGER` with the same confirmation removes what an interrupted run left, only the exact ledger entries whose run tag matches, and refuses a missing or empty ledger. It refuses the real Gateway and any other account or Region. The ledger must be inside `.local/gateway-harness`, flags must be spelled out in full, and its files are owner-only. Exit codes: 0 pass, 1 a check failed or stayed unknown or an unexpected error, 2 resources left behind, 3 refused (also any usage error). |
| **04e - Release identity** | `release_identity.py`, `prove_backend_login.py` | `release_identity.py check` only reads every hop, the interceptor Lambda's environment and the backend login proof; `interceptor` and `interceptor-delete` are dry runs unless given `--apply --i-understand-this-changes-aws`. Exit codes: 0 ok, 1 drift, 2 could not run or compare, 3 usage error or refused apply, 4 hops match but the service was not checked. `semantic-lambda` moves the semantic-search Lambda to the gateway login (grant first, then the variable; dry run unless given both flags). `deploy` runs `/opt/homebrew/bin/agentcore deploy -y` only after the live Gateway already reports the mode's authorizer and interceptor and `agentcore deploy --diff --json` plans no Gateway authorizer change, and it re-applies the `gateway` update if the deploy changed it; it refuses with exit 2 otherwise. The render deliberately keeps the Gateway resource on the stack's `AWS_IAM` in `jwt` mode (CloudFormation cannot change a Gateway's authorizer type and compares the template with the stack, not the live Gateway), so a live `CUSTOM_JWT` Gateway under an `AWS_IAM` template is expected; `check` and `deploy` compare the live Gateway with the mode. Change the Gateway authorizer only with `gateway`, and never run `agentcore deploy` bare in `jwt` mode. `check --expect iam` also reads both Runtime roles for `InvokeGateway`. `publish_gateway_parameters.py --gateway-login --apply` refuses (exit 2) until the holds role can read the gateway secret, which the first jwt deploy grants. `prove_backend_login.py` has the same flags, takes `--mode iam|jwt` (default: the mode in `.env`) and writes the receipt `check` verifies (exit 0 passed, 1 failed or crashed, 3 refused). The exit codes differ by tool; the table is in [Operations](../docs/OPERATIONS.md#read-the-release-back). |
| **04f - Prove identity** | `identity_proof.py` | Run after the release. Dry run by default (no AWS call): prints the probes and what would be refused. `--apply --i-understand-this-changes-aws` signs in as Jordan and the decoy (tokens in memory), probes the backend, both Runtimes, the Gateway and the database, writes a receipt under `.local/identity-proof/` and removes the two things Jordan's controls create. `--jordan-only` runs the controls; `--render RECEIPT` rebuilds the HTML pages. Exit codes: 0 pass, 1 failed or crashed or left something behind, 3 refused. See [Operations](../docs/OPERATIONS.md#prove-the-decoy-is-refused). |
| **04g - Identity captures** | `identity_capture/capture_session.py`, `identity_capture/mint_session.py`, `identity_capture/capture.mjs` | Run after the release. `capture_session.py` passes the two users' tokens over a private pipe to a headless browser that signs in without a typed password and captures the sign-in, the signed-in traveler, the RLS probe and the receipt. Writes PNGs under a folder you name. |
| **05 - Verify services** | `test_aurora_connection.py`, `test_semantic_search.py`, `verify_agentcore.py`, `smoke_gateway_tools.py`, `warm_demo.py` | Real AWS reads/invocations; these can incur model or service charges. In `jwt` mode `smoke_workflow_runtime.py`, `smoke_gateway_tools.py` and `smoke_production_turn.py` sign in as a seeded user through `agentcore_caller.py` (token from `cognito_tokens.py`, password from Secrets Manager); in `iam` mode they use the AWS credentials as before. `warm_demo.py` runs one read-only turn per phase (no holds) so the first turn on stage is not cold; `--hosted` warms the published site. |
| **06 - Exercise actions and recovery** | `smoke_production_turn.py`, `validate_demo.py`, `kill_and_resume_proof.py`, `lost_response_proof.py` | Live integration exercises, including writes. Read each script's help and cleanup contract; hosted full-run writes require an explicit flag. |
| **06b - Stop and resume proof** | `stop_and_resume_proof.py` | Stops a Runtime session and resumes it on a new microVM. `--during waiting` stops while the run waits for review; `--during running` stops while the hold step runs and exits 2 if the run finished first. Needs the backend on `MERIDIAN_PROOF_API`; removes its own rows unless `--keep`. |
| **07 - Publish** | `publish.py`, `published.py` | Review the CDK plan, apply to the established hosting resources, then inspect the non-secret local release record. Publication does not replace authenticated validation. |
| **08 - Maintain** | `release_demo_bookings.py`, `install_catalog_images.py` | Targeted booking release and catalog artwork installation. |

Retired manual cluster create/delete helpers and the orphaned root Node lockfile
were removed. Use the maintained CDK provisioning and teardown path. Local logs,
release receipts, generated configuration, credentials and build output stay
outside Git.
