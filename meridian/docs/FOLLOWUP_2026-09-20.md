# Deployment and UI follow-up - 20 September 2026

This report follows [the earlier E2E review](READINESS_2026-09-20.md). Earlier results remain historical. The [deployment runbook](DEPLOYMENT_FOLLOWUP.md) contains the current publisher, provisioning, migration, Finch and rehearsal procedures.

**Encryption assessment correction:** the original database and final rollback snapshot have `StorageEncryptionType=sse-rds`, so both were already encrypted with an AWS-owned key. The earlier assessment incorrectly treated `StorageEncrypted=false` as unencrypted storage. The migration was unnecessary for encryption at rest; it changes the key mode to `sse-kms` using an AWS-managed KMS key. This was disclosed during execution, and both clusters remain preserved. The preflight now reads the authoritative encryption type, with regression coverage for the misleading legacy flag. ## Aurora migration and hosted release

**Hosted release in progress.** The authorized replacement in account `619763002613`, region `us-east-1` has restored successfully through `MeridianAurora`. All 23 application table counts/content hashes and six metadata groups match the frozen source. A read/write/rollback transaction passed. Local and Gateway consumers use the replacement; a real SIGKILL/replacement-worker rehearsal preserved one hold and its original expiry, then cleaned its own records. App Runner is deploying the current image and replacement database binding. Hosted parity and the full live journey are still pending at this source checkpoint.

The source now has deletion protection, seven-day backup retention and a 0.5-16 ACU range. The replacement has explicit AWS-managed KMS encryption, TLS enforcement, a private writer, no inbound PostgreSQL port, Data API and stack termination protection. The already-encrypted source and its snapshot remain retained for rollback and continue to incur costs. Source application connections are disabled and its workload roles fenced. The original database credential must be retained while the replacement uses it; ancillary cleanup no longer deletes that shared credential.

The official [AWS Secrets Manager skill](https://github.com/aws/agent-toolkit-for-aws/blob/main/plugins/aws-core/skills/aws-secrets-manager/SKILL.md) and its `asm-exec` wrapper are available for this follow-up. Existing presenter access was imported write-only into `meridian/web/presenter`; edge access was not rotated. Verification resolves credentials only in the child process, without printing their values or committing local credential records.
