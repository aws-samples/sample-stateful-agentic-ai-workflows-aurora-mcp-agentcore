## Aurora migration and hosted release

**Execution in progress.** The user authorized the write freeze and encrypted replacement in account `619763002613`, region `us-east-1`. App Runner and both Gateway Lambda targets are paused, local Meridian backends stopped, source workload roles fenced, and application connections to the source database disabled. Final snapshot `meridian-pre-encryption-20260920-214526` is available. `MeridianAurora` is restoring `meridian-encrypted`; database parity and hosted validation have not yet passed at this source checkpoint.

The source already has deletion protection, seven-day backup retention and a 0.5-16 ACU range. The replacement template additionally enables storage encryption, TLS enforcement, a private writer, no inbound PostgreSQL port, Data API and stack termination protection. The source and its unencrypted snapshot remain retained for rollback and continue to incur costs. The original database credential must be retained while the replacement uses it; ancillary cleanup no longer deletes that shared credential.

The official [AWS Secrets Manager skill](https://github.com/aws/agent-toolkit-for-aws/blob/main/plugins/aws-core/skills/aws-secrets-manager/SKILL.md) and its `asm-exec` wrapper are available for this follow-up. Existing presenter access was imported write-only into `meridian/web/presenter`; edge access was not rotated. Verification resolves credentials only in the child process, without printing their values or committing local credential records.

## Remaining human and environment checks

- Timed 40-minute delivery and 20-minute discussion reserve, actual projector/back-row legibility, venue network, presenter access duration and event metadata require a person. The runbook includes a worksheet; no timings have been invented.
- Screen-reader task completion and event-specific accessible-PDF requirements remain open. Automated axe/zoom checks do not certify them.
- A fresh-account bootstrap, seed, rollback and teardown rehearsal remains separate. App Runner no longer accepts new customers; this publisher targets an established installation. New-account hosting needs a reviewed alternative.
- Retire the original Aurora cluster and unencrypted rollback snapshot only after an agreed rollback period. After writes reopen on the replacement, switching back without reconciling new writes would lose data.
